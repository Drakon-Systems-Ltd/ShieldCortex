## What shipped

### #77 — pluginStatus() false-negative (`b5a1feb`)
`shieldcortex openclaw status` only path-probed `~/.openclaw/extensions/shieldcortex-realtime`
and reported "config references … but no files on disk" on healthy managed-npm boxes.
`pluginStatus()` now falls through to the same install resolution the 4.47.3 loader
reconciler (#74) uses — `resolveRealtimePluginInstallPath` / `resolveRealtimeProjectDir`
(installs.json + `~/.openclaw/npm/projects/` scan) — before declaring the plugin absent,
reporting it as an `[managed]` install. The config-vs-disk drift path is preserved.
- Files: `src/setup/openclaw.ts`, `src/__tests__/openclaw-setup.test.ts` (+1 regression test).

### #76 — MCP self-heal + loud failure + PATH-immune config (`0816a4a`)
1. **Startup self-heal** (`src/setup/mcp-self-heal.ts`): at MCP boot a native-module
   (better-sqlite3 ABI) load failure triggers an in-place rebuild (`ensureNativeBinding`,
   scoped to the running install) and retries boot once. Wired into `startMcpServer`.
2. **Die loudly**: on unrecoverable failure, a one-line actionable stderr message + a
   breadcrumb at `~/.shieldcortex/logs/mcp-spawn-error.log` naming the install path and
   the repair command — never a bare JSON-RPC `-32000`.
3. **PATH-immune writers**: `resolveMcpServerCommand` (json-config.ts; copilot/codex) and
   `claude-md.ts` now emit an absolute node interpreter (`process.execPath`) + absolute
   `dist/index.js`. No shebang dependency, no `npx` hash-thrash. Fragile entries migrate
   on the next setup run.
4. **Multi-install repair** (`src/setup/install-discovery.ts`): `repair` discovers every
   install (self + PATH + `~/.claude.json` + `~/.codex/config.toml`), warns on a
   layer-split, and rebuilds + verifies each other install in a subprocess.
- The self-heal never restarts the gateway (only recompiles a native module on disk).
- Files: `mcp-self-heal.ts`, `install-discovery.ts` (new), `json-config.ts`, `claude-md.ts`,
  `native-binding.ts` (+`verifyNativeBindingInDir`), `index.ts`, `cli/repair.ts`; tests:
  `mcp-self-heal.test.ts` (7), `install-discovery.test.ts` (10); updated
  `copilot-setup` / `codex-setup` / `mcp-registration` expectations.

### #71/#72/#73 — mention-vs-intent FP tune (`7155f16`)
Classify-not-silence across three linked FP classes; detection preserved everywhere,
anti-bypass fixtures prove real attacks still catch.
- **#71 pipe-download-to-shell**: replaced the single regex with `pipeDownloadSignal()` —
  a fetch is RCE only when its bytes reach an interpreter as a PROGRAM (piped into a
  shell, a bare script interpreter with no `-c`/`-e`/`-m`/file, or a substitution whose
  output becomes code: `bash -c "$(curl)"`, `eval "$(curl)"`, `bash <(curl)`). Local
  substitution feeding no interpreter (`$(op item get …)`, `$(cat ~/.tok)`) and
  `curl … | python3 -c '<local>'` (JSON parsing) no longer match. `stripDataHeredocs()`
  drops literal quoted-delimiter heredoc bodies (documentation) — anti-bypass: an
  interpreter-fed heredoc (`bash <<'EOF'`) is kept and still blocks.
- **#72 llm_input host-runtime-notice**: OpenClaw's own gateway-restart notice / metadata
  envelope are downgraded from CRITICAL to a low-severity, filterable `host-runtime-notice`
  category — matched by SPECIFIC full wording anchored at the start, only the framing
  marker reclassified. Same strings embedded in user content, or a real injection riding
  alongside the notice, keep full severity.
- **#73 operator ops**: external-egress now requires an actual outbound payload
  (POST/PUT/upload/body) so a plain GET docs/release fetch is not gated; sudo capability
  probes (`sudo -n true`, `sudo -v`) are announced not denied; localhost CDP + headless
  Chromium pass; block reason codes now carry the rule id + matched signals instead of the
  opaque "approval error, failure policy: deny".
- Files: `tool-action-guard.ts`, `injection-scanner.ts`, `plugins/openclaw/interceptor.ts`;
  tests: `tool-action-guard.test.ts` (+24), `injection-scanner.test.ts` (+4),
  `plugins/openclaw/__tests__/action-guard.test.ts` (+4).

### Canary auto-dispatch — live in-process enforcement probe (`69b6a15`)
`defaultTriggerSyntheticOp` (unwired in 4.47.3) now drives a synthetic known-bad op
(`rm -rf / --no-preserve-root`, nonce-tagged) through the SAME in-process enforcement
engine the gateway loads (`evaluateToolCall`), requires a hard `block` verdict, then writes
a fresh nonce-tagged auto_deny audit entry that `findFreshEnforcementEntry` corroborates.
This is a live exercise of the enforcement CODE (not the #74 audit-log grep); if a
known-bad op is NOT denied it fails closed. Host-safe: `evaluateToolCall` is pure
recognition — the op is never executed and the gateway is never contacted. The
`JEST_WORKER_ID` guard stays effective; `SHIELDCORTEX_DISABLE_CANARY=1` is an opt-out; it
runs by default so enforcement is actively proven. Roster-absent / version-regressed remain
hard fails.
- Files: `src/setup/openclaw-selfcheck.ts`, `src/setup/openclaw.ts` (install hint + exit),
  `src/cli/doctor.ts` (hint); tests: `openclaw-canary-probe.test.ts` (+ end-to-end real-engine
  proof, fail-closed, JEST guard), `openclaw-plugin-selfcheck.test.ts` (source-shape updated).
