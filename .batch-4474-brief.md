## Workstreams

1. **#77 — pluginStatus() false-negative.** `shieldcortex openclaw status` only path-probes `~/.openclaw/extensions` and is blind to managed npm project installs, so it reports "no files on disk" on healthy boxes. Make it resolve managed/registry installs (same resolution the 4.47.3 loader reconciler uses via installs.json/canonical dirs) before declaring files missing.

2. **#76 — MCP self-heal + loud failure.** MCP server dies with bare -32000 on native-module ABI mismatch (better-sqlite3); setup writers emit PATH-fragile entries. Add: startup self-heal (detect ABI mismatch → attempt rebuild/repair path), a loud actionable error instead of bare -32000, and PATH-immune config entries (absolute binary paths) from setup writers.

3. **#71/#72/#73 — mention-vs-intent FP tune.** Three linked FP classes: (a) pipe-download-to-shell fires on 1Password CLI command substitution and quoted/documentation content; (b) llm_input injection detector flags OpenClaw runtime notices and metadata envelopes as CRITICAL; (c) aiquant field report — over-blocking operator-directed ops (localhost CDP, docs fetch, local npm, sudo probe) with opaque reason codes. Direction agreed on the issues: classify-not-silence (downgrade classification, don't delete detection), distinguish mention vs intent (dangerous strings as quoted TEXT/data ≠ executable intent), and add anti-bypass fixtures proving real attacks still catch. Also make block reason codes human-readable.

4. **Canary auto-dispatch.** `defaultTriggerSyntheticOp` in `src/setup/openclaw-selfcheck.ts` is deliberately unwired (fail-closed) in 4.47.3 — it reports "roster proof stands; enforcement not actively proven". Wire an active synthetic-op dispatch so the enforcement canary is a live probe, NOT an audit-log grep (that was the #74 lie). It must prove the interceptor is live in-process; on any uncertainty it must still fail closed. Keep the hard-fail behaviour for roster-absent / version-regressed.
